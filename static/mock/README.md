# 障碍层 mock 数据（前端联调用）

这套数据让前端不依赖机器人在线就能把解码和叠加渲染全部跑通。地图用的是真实站点图 `16f01`（547 × 611，每格 0.05 米），所以坐标、尺寸、`origin` 都和现场一致，前端手上那张 PGM 可以直接当底图。

消息体字段的含义见同目录 `FRONTEND-API.md`，本文只说这批文件怎么用。

## 一、最快的验证方式

双击打开 `preview.html`。它内嵌了底图和全部帧，不需要起服务、不需要联网，打开就能看到：

- 底图 + 层 A + 层 B 三个开关，可以单独看每一层
- 五帧连续播放，模拟行人走动时层 A 每秒整层替换
- 鼠标移到画面上实时显示该点的世界坐标（米），用来核对 `origin` 换算
- 页面底部就是解码函数的源码，和给前端的那段完全一致

如果前端自己的实现和这个页面显示得不一样，问题在前端这边。

## 三、打开后应该看到什么

- **层 A**：走廊里两个小圆点（行人）和一个方块（箱子），另外在中庭的灰色未知区里有一个小点。最后这个点是故意放的——层 A 的判据是「地图上不是墙」而不是「地图上是空闲」，所以未知区里的观测同样会进层 A。前端看到未知区里冒出障碍不是误报。
- **层 B**：沿所有墙体的一条均匀蓝带，比墙本身宽出约 3 个像素。这就是 0.16 米的膨胀带（机器人 footprint 的内切半径），不是画错了。
- **五帧连播**：只有左边那个行人在动，其余不变。每帧都是整层替换，不是增量。

## 四、验收清单

前端接完之后逐条对一遍：

1. 解出的数组长度必须等于 `msg.count`，对不上就是解码链哪一步错了（最常见是漏了小端标志或没做前缀和）。
2. 喂 `obstacles_lethal_empty.json` 之后，画面上的红点必须**全部消失**。`count = 0` 是「这一层现在没有内容」，不是「没收到数据」。注意它的 `data` **不是空串**，而是一个能正常解码、解出零个元素的合法串，判空帧一律看 `count`。
3. 上下方向用非对称地标核对：这张图下方有几处向外的走廊开口，上下颠倒的话它们会跑到画面顶部。左右大致对称的地图，颠倒了也「看着挺合理」，必须找不对称的特征来判。
4. 层 A 和层 B 分别用各自的图层，收到哪条替换哪条，不要合并成一个数组。

## 五、和真实数据的差异

- **编码链完全一致**：`u32delta + gzip + base64`，与 `nav_egress` 的 `grid_index_codec` 同算法，前端在这里跑通就等于在真机上跑通。
- **障碍内容是构造的**，不是真机抓包。行人和箱子的位置由脚本按「离墙最远的空地」自动选点，不代表现场真会在那里。
- **层 B 的膨胀用圆盘近似**，nav2 实际用的是距离变换，边界上可能差一两格。这个差异对渲染没有影响，但别拿这批数据去核对导航行为。
- 五帧的 `stamp` 按每秒递增构造，`frame_id` 固定 `map`。
